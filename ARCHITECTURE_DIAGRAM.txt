5. SECURITY LAYERS
================================================================================

┌──────────────────────────────────────────────────────────────────────────────┐
│                          SECURITY DEPTH                                      │
└──────────────────────────────────────────────────────────────────────────────┘

Layer 1: NETWORK
    └─ HTTPS only (encrypted in transit)
    └─ All requests go through Supabase Edge Functions

Layer 2: AUTHENTICATION
    └─ OAuth2 (Google) or Email/Password
    └─ Passwords hashed with bcryptjs
    └─ JWT tokens for session management

Layer 3: APPLICATION
    └─ Session verification in API routes
    └─ Validate user ownership before operations
    └─ Input validation and sanitization

Layer 4: DATABASE
    └─ Row-Level Security (RLS) policies
    └─ Foreign key constraints
    └─ Data type validation

Layer 5: AUDIT
    └─ All changes logged to audit_log
    └─ IP addresses recorded
    └─ Before/after values captured

Attack Vector Examples + Defense:

    ┌─────────────────────────────────────────────┬────────────┐
    │ Attack                                      │ Defense    │
    ├─────────────────────────────────────────────┼────────────┤
    │ Try to fetch user #2's data                 │ RLS        │
    │ Cross-user data leak                        │ Policy     │
    ├─────────────────────────────────────────────┼────────────┤
    │ SQL injection in API                        │ Parameterized
    │ (malicious SQL in query)                    │ Queries    │
    ├─────────────────────────────────────────────┼────────────┤
    │ Man-in-the-middle (intercept traffic)       │ HTTPS +    │
    │                                             │ Encryption │
    ├─────────────────────────────────────────────┼────────────┤
    │ Brute force password attack                 │ Bcryptjs   │
    │ (crack hashed password)                     │ + 10 rounds│
    ├─────────────────────────────────────────────┼────────────┤
    │ Delete other user's data                    │ Foreign Key│
    │ (bypass app logic)                          │ Constraint │
    └─────────────────────────────────────────────┴────────────┘

│                        AUTOMATIC TRIGGERS                                    │

Trigger #1: on_auth_user_created
    WHEN: User signs up
    ACTION:
        ├─ Create profiles row
        ├─ Create user_settings row
        └─ Create audit_log entry
    RESULT: No manual provisioning needed

Trigger #2-7: update_*_updated_at
    WHEN: Any row updated in [profiles, user_settings, favorites,
                              journal_entries, prayer_history]
    ACTION: Set updated_at = NOW()
    RESULT: No app code needed to set timestamps

9. BACKUP & DISASTER RECOVERY
================================================================================

Supabase Automatic Backups:
    │
    ├─ Free Plan:    Weekly backups (7 days retention)
    │   Daily uploads to S3
    │
    └─ Pro Plan:     Daily backups (30 days retention)
        Daily uploads to S3

Restore Procedure:
    1. Contact Supabase support OR
    2. Use Supabase Dashboard > Project Settings > Backups
    3. Select backup date
    4. Click Restore
    5. Verify data integrity
    6. Notify users of recovery

Test Restore Quarterly:
    ✓ Ensures backups work
    ✓ Identifies any data loss
    ✓ Trains team on recovery
